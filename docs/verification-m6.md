# M6：可靠提交、昵称与草稿

开发日期：2026-10-29。本阶段完成请求级防重复提交、真实微信昵称设置、活动/方案/账单草稿恢复。待办中心、服务端列表分页和 CI 留待后续阶段。

## 请求级防重复

- 迁移 v7 新建 `idempotent_requests`，不修改已有活动与财务记录。回执按用户、接口路径和请求编号联合隔离。
- 活动创建、方案创建/修订、账单创建/修订支持 `Idempotency-Key`。相同编号和规范化输入返回首次成功结果；同一编号的不同输入返回 409。不同编号允许内容相同的真实消费。
- 回执和业务修改在同一个立即事务中提交；失败全部回滚。独立进程通过 SQLite 写锁协调，进程重启后仍可重试。
- M6 表单发送前先将编号和内容保存在草稿里。退出后恢复并原样重试复用编号，提交成功后清除草稿。修改提交内容会产生新编号，视为一次新的操作。
- 旧客户端未发送编号时继续兼容原行为，不具有新增操作的重试去重保证。既有收款确认的幂等规则保持不变。本阶段不自动重试写操作，也不生成离线提交队列。

## 昵称

“我的 → 修改昵称”可设置 1–24 个字的名字，拒绝空白、换行/控制字符及越权字段。GET `/me` 和 POST `/me/profile` 均校验当前身份，响应只返回公开用户字段，不返回微信标识。

服务端更新当前微信用户；现有会话继续有效，成员名单和正常账单的成员读取显示新名字。冻结/归档中的历史快照保持原样。固定 A–E 演示身份不可改名。

前端同步缓存中的用户资料，保留原会话令牌。较早的资料刷新不会覆盖刚保存的昵称，切换身份后的旧请求不覆盖新会话。

## 草稿

- 覆盖发起活动、新建/修订方案、新增/修订账单，以及凭证页可选记账表单。保存未完成的原始输入，包括金额文本、分摊方式和已选关联，不要求草稿已符合提交规则。
- 草稿按 API 地址、身份模式、用户和活动/对象隔离，仅保存到本机。无会话令牌、openid 或密钥；未登录不创建草稿。
- 页面恢复显示提示，支持确认后清除。初始化、恢复和清除不会反过来将空表单覆盖到保存的草稿。
- 编辑草稿绑定服务器版本。版本变化时提示重新对照填写，不将旧草稿直接套用到新版；新增编辑后替换该对象的旧草稿。
- 本机存储失败会明确提示；提交编号不能持久化时阻止发出写请求。成功后清除本机草稿；登录身份变化后的迟到成功响应不会触发旧表单跳转。
