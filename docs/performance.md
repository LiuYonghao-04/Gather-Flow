# M5 性能记录

2026-10-20，Windows、Node 22.18.0。本记录是本机微基准，不代表生产吞吐量、网络延迟或手机帧率。

## 费用汇总

`npm run benchmark` 创建独立的内存 SQLite：5 名成员，每笔账单 3 次修订，当前修订有其他分摊者确认。预热一次，测量 12 次 `finance()` 加 JSON 序列化。断言账单数量和已确认金额，数据库随后关闭，不接触本地演示库。

原实现逐笔查修订、确认、异议，并重复读取整个活动的凭证。M5 按活动批量读取，再按账单 ID 归组，凭证只查一次；读事务保证同一次汇总的一致性。账单详情复用相同逻辑，历史与权限保留。

| 账单数 | 原中位数  | M5 中位数 | 原 P95    | M5 P95   | JSON 字节数 |
| ------ | --------- | --------- | --------- | -------- | ----------- |
| 50     | 4.87 ms   | 1.51 ms   | 9.42 ms   | 2.59 ms  | 92,276      |
| 200    | 18.09 ms  | 5.66 ms   | 29.23 ms  | 6.49 ms  | 365,928     |
| 1,000  | 108.21 ms | 27.72 ms  | 131.53 ms | 30.38 ms | 1,826,737   |

基线在修改前实测；M5 数据来自最终加入读事务后的运行。12 次样本较少，中位数取排序后的第 7 个样本（上中位数），P95 为最大值。后台进程、硬件和缓存会影响结果，不在 CI 中断言耗时阈值。回归测试断言从 1 笔增长到 21 笔时 SQL 查询数不增长，以及跨活动隔离、详情/汇总一致和修订、确认、异议历史不丢失。

## 仍有的边界

- 费用页面首批只渲染 20 笔，审计接口每页 50 条。费用接口仍一次返回全部账单及历史；1,000 笔约 1.83 MB，未来需要服务端列表分页和详情按需读取。
- 活动、方案和成员按小型朋友群设计，尚未压测高并发写入。SQLite 的立即事务用于正确串行化竞争，不意味着支持任意规模。
- 微信正式构建约 0.33 MB 原始文件，18 个页面；这是文件大小总和，不是微信上传压缩包或审核结果。
- 未测真机首屏、FPS、弱网图片上传与峰值内存；没有将 H5 或模拟器数据冒充真机数据。

原始结果保存在被忽略的 `output/benchmark-current.json`。`--baseline` 仅改变输出文件名，不切换旧实现；重新测旧基线应使用 M4 源码和相同样本脚本。
