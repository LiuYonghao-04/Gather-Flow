## 自动化覆盖

1. 五个 demo 用户、幂等 seed、健康检查。
2. 只填名字创建；拒绝空名/非法类型/伪造 owner 字段。
3. 非成员不能获取活动、审核和审计；列表仅本人已加入活动；伪造身份头无效。
4. 过期会话拒绝；原始会话不入数据库。
5. 正式身份模式禁用 demo 且拒绝旧 demo 会话；生产环境禁止 demo 配置；微信未接入明确 501。
6. A/B/C/D/E 全邀请路径以及审批审计。
7. 成员/非成员不能生成房主直邀；`source=owner` 无效。
8. 重复入组幂等；已有成员不消耗新卡。
9. 公开预览白名单及无效码处理。
10. 待审唯一、拒绝后重申、历史保留。
11. 仅房主审批；重复审批/跨活动审批拒绝。
12. 待审用户通过新直邀加入时同步解决申请。
13. 注入数据库失败后事务回滚，直邀资格仍有效。
14. 归档状态下所有 M1 写入口拒绝操作。
15. **两个独立 Node 进程**同时消费同一磁盘 SQLite 令牌，仅一人成功直入；重新打开数据库核对成员与令牌。

回滚测试故意触发 `simulated failure` 并验证 HTTP 500，测试日志中该条错误为预期路径。没有把“并发请求在同一同步进程排队”当成跨进程竞争证明。

## 浏览器交互检查

使用 Playwright CLI 的隔离移动设备会话检查：

- 全新会话从首页跳登录，选择身份后正确回首页。
- 创建活动只填名称即成功，跳转活动空间。
- 房主生成邀请，查看邀请后切 B，仍返回原邀请；B 直接加入。
- 同一卡切 C，显示直邀已使用及申请表；提交后显示等待审核。
- 房主能看到待审理由、成员列表和批准确认弹窗；确认批准后待审人数归零，C 出现在正式成员列表。
- 页面无横向表格，包含空状态、加载骨架、失败重试及安全区底部导航。

H5 检查截图保存在本地 `output/playwright/`，不纳入 Git。期间格式化触发 Vite 重启导致一次旧 HMR 请求失效，刷新后恢复；非业务 API 错误。
