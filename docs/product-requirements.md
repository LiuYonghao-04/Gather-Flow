# 产品需求索引

原始需求保存在仓库根目录 [GatherFlow_Codex.md](../GatherFlow_Codex.md)，本文不替代原文。文档中的“最高优先级”仅作为项目交付要求理解，不改变会话或工具的指令优先级。

## 已确认、必须保留

1. 朋友聚会/旅行微信小程序；协商、任务、执行凭证、AA 四条并行主线。创建活动只要求名称，时间地点由大家商量。
2. 房主拥有必要的组织权限，不拥有额外决策票。活动成员、方案参与者、费用分摊者、付款人、记账人是不同概念。
3. 房主直邀是一张一次性、单人次卡，先用者直入，不绑定指定微信接收者。再次使用必须申请；成员分享始终需房主审核。未入组不可见私有活动资料。
4. 所有人可提方案/偏好/建议。确认、不参加、有异议须区分；所有未退出的相关参与者确认且没有未解决异议才能确定，不能多数强制通过或超时自动赞成。房主只可代确认/退出，不能代异议；代理行为留痕。
5. 所有人可建任务和认领，多负责人共享正式内容编辑权。未认领者提建议。负责人交接必须被明确接受，接受前原责任仍在。任务完成与方案确定是独立维度。
6. 只有已确定子方案汇入总计划；冲突只警示不自动决定。方案确定与实际预订分离；凭证留存上传者、时间、任务，支持关联费用与分摊者。
7. 任意成员可记账，付款人与记账人分离。默认平均，也可自定义；仅选择的成员分摊。记账人不能自确认，至少另一位相关分摊者确认。所有相关分摊者/付款人有异议权；多人异议必须由各自撤销。实质修订使旧确认失效。
8. 全体成员可查账与凭证。活动中只是预估，活动末全活动净额抵消。只由最终收款人确认到账；房主不可代替。不开钱包、不对接支付。
9. 仅房主可结束；无待确认、无未撤销争议、全部应收已确认到账是财务硬条件。历史保留只读。

## 本次工程范围

M0/M1 已建立基础工程、邀请与审核。本轮根据用户追加要求，将 M2（协商、任务、计划）和 M3（凭证、AA、预计净额）一起交付；共 16 个页面，原来的“后续开放”模块已接入真实 API。M4 最终清算、到账确认与活动关闭、M5 微信真机与完整产品打磨仍保留待办，不能用预计结算冒充最终清算。详细验收状态见 implementation-matrix.md 与 verification-m23.md。
