# 3–5 分钟项目演示

## 提前准备

先运行 `npm run dev`，再运行 `npm run demo:m5`。这会通过五个独立会话执行真实 HTTP 请求，从邀请审批到最终归档，数据落入 SQLite。脚本重复运行只新增演示活动。保留输出的归档链接，并在首页找到同名活动。所有姓名、订单图片及到账操作都是虚构演示。

若要现场演示冻结、收款、结束这些写操作，另跑一次 `npm run demo:m23`，保留待确认的停车费。归档样本用于稳定回看，现场样本用于交互。

## 展示顺序

| 时间      | 页面与动作                                      | 讲清楚的设计                                                                     |
| --------- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| 0:00–0:35 | 登录页切 A/B，打开活动和成员页                  | 五个身份共用真实服务端数据，房主审批不等于拥有替别人决定方案的权力               |
| 0:35–1:25 | 协商页查看日期方案、E 的限制与异议历史          | 四人确认不会覆盖一个人的异议；本人退出只作用于当前方案；修改内容需重新确认       |
| 1:25–2:00 | 路线任务查看 C→D 交接，再看三日行程             | 接手前责任不移除；任务完成、方案确定和实际执行是不同状态；冲突提醒不替用户改时间 |
| 2:00–3:00 | 查看 800 元票款、48 元饮料及凭证                | 部分成员分摊、整数分尾差、自定义合计、其他相关成员确认、异议本人撤销             |
| 3:00–4:10 | 现场样本确认停车费，冻结，切 B，再切 A 确认收款 | B 是付款人却不能代收款方确认；A 收款前能重开，收款后不能自动重算                 |
| 4:10–4:40 | 结束后查看相聚档案，或打开提前准备的归档样本    | 服务端拒绝归档写入，仍能追溯所有账单、快照、行程与任务                           |
| 4:40–5:00 | 简述测试和性能证据                              | 严格类型、权限和并发回归；批量读取减少费用查询，具体口径见性能记录               |

## 可核实的技术表述

- “使用 uni-app、Vue 3、TypeScript 和 Pinia 实现微信小程序，Express + SQLite 保存协商版本、账单修订与清算快照。”
- “把方案共识、任务责任、执行进度和财务状态拆开处理，通过服务端权限、版本校验和事务防止越权及过期写入。”
- “使用整数分与确定性净额配对消除环形债务，验证金额守恒、不自转账；不宣称求解全局最少转账次数。”
- “本机 1,000 笔、每笔 3 修订的费用汇总和序列化，中位耗时由 108.21 ms 降到 27.72 ms；没有把微基准当作线上性能指标。”

真实微信身份登录尚未接入，当前为本地 demo。微信发送分享、手机照片选择/上传和真机网络仍需单独验收。演示时应明确这些范围，不宣称已上线或真实资金结算。
