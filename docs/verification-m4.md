# M4 验证记录

完成日期：2026-10-20（Asia/Shanghai）。基于 M2/M3 提交 `965e6c3`，在 `codex/m4` 实现最终清算、到账确认、活动结束及只读归档。环境为 Windows、Node 22.18.0、npm 10.9.3。

## 实现范围

- 第 4 个增量迁移：不可变清算快照、逐笔转账、收款人/时间、重开历史、活动归档人/时间。原有 SQLite 数据保留。
- 房主在账单无待确认、无异议时冻结；保存成员、账单修订与内容、净额及转账清单。冻结后禁止账单写入和新增成员。
- 尚无任何到账可由房主重开，旧快照失效但保留；已有到账禁止重开。旧快照、旧财务版本及不匹配转账均被服务端拒绝。
- 仅最终收款人确认整笔到账；重复请求幂等，房主和付款人没有代理权限。确认、重开、关闭均在立即事务中处理并写审计。
- 房主结束前再次检查财务状态及全部到账。无共享费用可显式生成零转账快照并结束，非财务任务未完成不阻止结束。
- 新增清算页、归档页，共 18 个页面；已冻结/归档账单隐藏写入口，归档展示计划、任务、消费、凭证、净额、到账和审计入口。

## 五人演示与页面验收

`npm run demo:m4` 每次新建一场演示，先执行 M2/M3，再确认停车费，将共同总额从 848 元更新到 868 元。最终 A 净应收 618 元，B/C/D/E 分别应付 15/213/190/200 元。脚本核验四笔收款、重开保护、房主结束，以及五个成员均可读取档案。输出位于被 Git 忽略的 `output/m4-demo.json`。

使用 Playwright CLI 的 iPhone 13 移动视口进行了实际 H5 操作：

1. 登录深链接返回清算页；普通成员 B 只可查看，无冻结、收款或结束按钮。
2. 房主 A 冻结、二次确认后重开、再次冻结为第 2 份，历史保留第 1 份失效清单（2026-10-19 验证）。
3. 2026-10-20 重启服务后保留原快照和待收款状态，切换 B/A，收款人 A 经二次确认逐笔确认四笔演示到账。
4. 第一笔到账后重开入口消失，仍显示三笔待到账，不能结束；全部到账后才出现可用的结束按钮。
5. 房主明确结束并跳转只读归档，展示共同支出、三日安排、未完成任务、最终净额与收款记录。
6. 从归档进入费用列表及原记账人的账单详情，均显示只读提示，没有新增、修改、确认或异议操作。最终浏览器控制台为 0 errors / 0 warnings。

截图位于本地 `output/playwright/`（不提交 Git），包括 `m4-archive.png`、`m4-settled.png` 和 `m4-archive-final.png`，已检查移动端布局。假凭证为纯色图，无真实订单或收款。
