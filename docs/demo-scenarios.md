# M1：五人邀请与审批演示

## 准备

运行 `npm run dev`。在微信开发者工具导入 `apps/miniapp/dist/dev/mp-weixin`；也可同时运行 `npm run dev:h5`，在 `http://localhost:5173` 辅助演示。首次登录有 A/B/C/D/E 五位虚构朋友。

当前演示覆盖 M0/M1，不包含协商、任务、记账和清算；不要把后续模块标记为已完成。

## 手动路径（约 3–5 分钟）

1. **A 林间创建活动。** 登录 A，点击底部加号。仅填写“周末三日游”，不填时间、地点、类型或简介。创建后进入活动空间。
2. **A 直邀 B。** 点击“邀请朋友”，等待生成。复制邀请页面路径并保存为卡片 1。点击“查看邀请”→“切换身份”→B 陈屿，仍然回到这张邀请。B 点击接受，直接加入。
3. **同一卡片给 C。** 回到首页，点击“打开邀请”并粘贴卡片 1，在邀请页切到 C 许知夏。看到“直邀已被使用”，只能申请。提交后显示待房主审核，不能看到成员或活动内容。
4. **B 邀请 D。** 切回 B，从活动空间进入“邀请朋友”，复制卡片 2。查看邀请并切 D 周予安，始终只能申请。
5. **A 审批。** 首页切 A，活动卡显示“2 人待审核”。进入“同行的朋友”，分别同意 C 和 D；也可先拒绝 C，再让 C 用同卡重新申请，展示历史保留。
6. **A 新直邀 E。** A 从活动空间生成新卡 3，打开并切 E 沈念，直接加入。活动成员页显示完整五人。
7. **审计回看。** 任一已入组成员查看“活动足迹”，可见谁发起、谁邀请、谁申请、谁审批。刷新页面不会丢失数据库状态。

本地模拟时“复制这张邀请”保留同一原码，便于验证消费后的行为。原生“分享给微信朋友”每次使用一张预生成新卡，已有卡的转发不变。微信分享本身需要有效 AppID 和工具/微信环境，未用 H5 剪贴板操作冒充真实微信发送。

## 自动路径

API 运行时执行 `npm run demo:m1`。脚本用五个服务端会话发送真实 HTTP 请求，断言：

- B 首次直入；C 同卡返回 `APPROVAL_REQUIRED`。
- B 的成员邀请不能让 D 免审核。
- A 待审列表恰好有 C、D；逐一批准后创建成员关系。
- E 通过另一个新码直入。
- 最终成员恰为 A/B/C/D/E，审计恰好 10 条。

每次创建独立演示活动，不重置或覆盖已有活动。脚本不会打印 bearer 或邀请码。
