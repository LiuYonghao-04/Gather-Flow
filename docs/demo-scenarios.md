# 五人演示：邀请、协商、任务与 AA

## 准备

运行 `npm run dev`。在微信开发者工具导入 `apps/miniapp/dist/dev/mp-weixin`；也可同时运行 `npm run dev:h5`，在 `http://localhost:5173` 辅助演示。首次登录有 A/B/C/D/E 五位虚构朋友。

M1 邀请流程与 M2/M3 协作财务流程均可演示。最终清算与活动结束属于尚未实现的 M4。

## 手动路径（约 3–5 分钟）

1. **A 林间创建活动。** 登录 A，点击底部加号。仅填写“周末三日游”，不填时间、地点、类型或简介。创建后进入活动空间。
2. **A 直邀 B。** 点击“邀请朋友”，等待生成。复制邀请页面路径并保存为卡片 1。点击“查看邀请”→“切换身份”→B 陈屿，仍然回到这张邀请。B 点击接受，直接加入。
3. **同一卡片给 C。** 回到首页，点击“打开邀请”并粘贴卡片 1，在邀请页切到 C 许知夏。看到“直邀已被使用”，只能申请。提交后显示待房主审核，不能看到成员或活动内容。
4. **B 邀请 D。** 切回 B，从活动空间进入“邀请朋友”，复制卡片 2。查看邀请并切 D 周予安，始终只能申请。
5. **A 审批。** 首页切 A，活动卡显示“2 人待审核”。进入“同行的朋友”，分别同意 C 和 D；也可先拒绝 C，再让 C 用同卡重新申请，展示历史保留。
6. **A 新直邀 E。** A 从活动空间生成新卡 3，打开并切 E 沈念，直接加入。活动成员页显示完整五人。
7. **审计回看。** 任一已入组成员查看“活动足迹”，可见谁发起、谁邀请、谁申请、谁审批。刷新页面不会丢失数据库状态。

本地模拟时“复制这张邀请”保留同一原码，便于验证消费后的行为。原生“分享给微信朋友”每次使用一张预生成新卡，已有卡的转发不变。微信分享本身需要有效 AppID 和工具/微信环境，未用 H5 剪贴板操作冒充真实微信发送。

## 自动路径

API 运行时执行 `npm run demo:m1`。脚本用五个服务端会话发送真实 HTTP 请求，断言：

- B 首次直入；C 同卡返回 `APPROVAL_REQUIRED`。
- B 的成员邀请不能让 D 免审核。
- A 待审列表恰好有 C、D；逐一批准后创建成员关系。
- E 通过另一个新码直入。
- 最终成员恰为 A/B/C/D/E，审计恰好 10 条。

每次创建独立演示活动，不重置或覆盖已有活动。脚本不会打印 bearer 或邀请码。

## M2/M3 自动准备与手动演示（约 5 分钟）

API 启动后执行 `npm run demo:m23`，打开脚本输出的活动链接，登录 A 林间。每次运行创建新活动并保存到 SQLite。脚本断言真实服务响应，不通过修改数据库造结果。

1. **一起商量**：查看“周六出发”方案，E 的“只有周日有空”限制和讨论仍保留。E 的异议经本人选择退出解决，其余四人确认。每次退出仅适用于该方案，其他独立方案可另行选择参与。
2. **任务分工**：查看“三日慢游路线”，内容由 C 写好、C→D 的交接已被 D 接受，B 的建议还在。新增任务并认领，试着编辑正式内容或增加共同负责人。切换未认领的成员，看到建议入口而不是编辑权限；可以自行认领共同负责。
3. **总行程**：按三天聚合已确定安排，第一天高铁 14:00 抵达与 12:00 溪谷散步有冲突提示，时间不会被系统自动改写。
4. **预订与凭证**：A 查看去程高铁任务与方案，分别展示工作完成、方案确定、实际已预订。凭证是脚本生成的纯色假图，只能成员查看。继续上传 `output/demo-evidence.png`，在同页打开“顺手把这笔费用记上”，关联刚才图片，不必重传。
5. **800 元票款**：在费用页查看 A/C/D/E 各 200 元，B 不承担；C 一人确认后已生效。A 的 200 元个人消费不会生成给自己的转账。
6. **48 元饮料**：自定义 A20 / B15 / C13，B 确认，C 提过异议并自行撤销，所有记录保留。可切 C 再提异议，看到预估排除该账；切 A 不存在替 C 撤销的按钮，再切 C 本人撤销。
7. **预计结算**：初始已确认总额 848 元；D 记的 20 元停车费待 A 确认，暂不纳入。净额先抵消、再展示预计转账；页面明确不是最终清算。
8. **版本与审计**：改一份尚未执行的方案，新版需重新确认；原记账人修改账单也会使原确认失效。所有成员可在活动足迹及详情历史回看。

`output/m23-demo.json` 保存本次活动、任务、方案、账单 ID，不包含会话凭据。可在首页列表重新找到演示活动，或用输出链接打开；刷新不丢失数据。
